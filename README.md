# 1 on 1 street basketball

## ゲームのルール
本格的な「1 on 1」のストリートバスケットボールゲーム。
先に7点先取した方が勝利となる。
実際の3x3公式ルールを採用しており、攻守が交替した際（相手のシュート後やリバウンドを取った時）は、一度3Pラインの外に出る「クリアアウト」を行わないとシュートが打てない（画面に警告が出る）。
3Pライン外からのシュートは2点、ライン内からのシュートは1点として加算される。

## 操作方法
[ 1 ]: イージーモードでゲームスタート（NPCがスティールを行わない初心者向け）
[ 2 ] [ Enter ]: ノーマルモードでゲームスタート（標準的な難易度）
[ 3 ]: ハードモードでゲームスタート（NPCの移動速度が上昇する高難易度）
[ ↑ ↓ ← → ] : プレイヤーの移動
[ Space ] : (オフェンス時) ジャンプシュート / (ディフェンス時) ブロックジャンプ
[ V ] : レイアップ（ゴール付近で使用、打点が低く速いシュート）
[ C ] : フロントチェンジ（NPCが近くにいると50%の確率でアンクルブレイクが発動し、敵が一定時間硬直します）
[ F ] (長押し) : ダッシュ（移動速度が通常よりアップします）
[ S ] :スティール（ディフェンスの時敵に接近してボールを奪う）

## 工夫点
第1の工夫はゲームロジックとAIの実装である。実際の3x3公式ルールである「クリアアウト」を導入し、攻守交替時にボールを一度3Pラインの外へ運ぶ処理を、ゴールからの距離計算を用いて厳密に判定。また、NPCのAIにもこだわり、ボールを奪うと自ら3Pライン外へドリブルで運ぶ賢い挙動や、Cキーによる「アンクルブレイク（確率での硬直状態）」など、対人戦のような駆け引きを実装した。
第2の工夫は描画と物理演算である。キャラクターの手足の滑らかな振り子運動や、ドリブル時の自然なボールのバウンドは、時間経過を変数とした三角関数を用いて表現している。さらに、シュートのブレ幅をゴールからの距離やディフェンスとの距離で動的に変化させ、リアルなシュート確率を再現した。
第3の工夫はモジュール化によるコードの最適化である。数百行に及ぶプログラム全体を、ヘッダーファイル(common.h)と3つのソースファイル（メイン、描画、ロジック）に分割した。変数や状態フラグをexternで適切に管理することで、バグを防ぎつつ拡張性と可読性を高くした。

## システム面の工夫
・3x3ルールの完全再現と動的UI
ボールの所有権（ballOwner）が移行した際やシュートが決まった直後に、mustClearフラグを有効化する仕組みを実装した。キャラクターの現在座標とゴール座標からsqrt関数を用いて三平方の定理で正確な距離を算出し、3Pライン（距離7.0f）の外に出るまでシュート入力をシステム的に無効化している。同時に、クリアアウトが必要な状況では画面上に警告テキスト（HUD）を動的に描画し、プレイヤーへルールを伝達する工夫を取り入れた。

・ステート（状態）管理による入力制御の最適化
キーボード入力の処理において、isOffense（ボール所持時）とisDefense（非所持時）のフラグを用いてプレイヤーのステートを毎フレーム明確に定義している。これにより、同じ[Space]キーの入力でも、状況に応じて「放物線を計算されたジャンプシュート」と「敵のシュートを妨害するブロックジャンプ」へと処理が安全かつ正確に分岐する。条件分岐のネストを浅く保ち、操作の暴発やバグを防ぐ堅牢なコードとした。

・自律型NPCのAI設計とボディコンタクト（当たり判定）
プレイヤーとNPCの間に距離0.8fを閾値とする当たり判定を設け、判定内に侵入した場合は座標を直前の位置（oldX, oldZ）に巻き戻す処理を実装した。これにより「体で進路を塞ぐ」という実際のバスケ特有のフィジカルなディフェンスを実現している。またNPCは単なる追従ではなく、「ルーズボールを最短距離で拾う」「ボール奪取後は自ら3Pライン外周へ向かってクリアアウトを行う」「フリーの隙を見計らってシュートを放つ」といった、人間らしい状況判断を行うよう自律的に構築した。

・タイマー制御と乱数によるアクション性の拡張
フロントチェンジ（Cキー）を実行した際、NPCとの距離が一定以内であれば、乱数を用いて50%の確率でNPCの動作タイマー（npcStunTimer）を操作し、一定時間強制的に硬直させる「アンクルブレイク」を実装した。これとFキー（長押し）によるダッシュの移動速度変更を組み合わせることで、フェイントで敵の足を止めてから一気に抜き去るという、戦略的かつ爽快なゲームプレイを生み出している。

・動的なシュート確率（プレッシャー判定）の算出
シュートのブレ幅を決定する変数（errorFactor）を固定値にせず、ゴールまでの距離に応じて基礎数値を算出。さらに、シュートを打つ瞬間のディフェンスとの距離や、ブロックジャンプの有無をリアルタイムで判定し、強いプレッシャーがかかっている場合はブレ幅を最大5倍に増大させる処理を組み込んだ。「オープンな状態なら入りやすく、マークされていると外れやすい」という現実のシュート精度を、物理演算の誤差としてシステムにした。シュートの軌道を実装するのが難しく、違和感ない放物線を描きなおかつ点が決まる軌道を設定するのに苦労した。
// ボールの初速（ベクトル）を、乱数によるブレを含めて決定する。
ballVX = (dx / frames) + ((float)rand() / RAND_MAX * 2.0f - 1.0f) * errorFactor;
ballVZ = (dz / frames) + ((float)rand() / RAND_MAX * 2.0f - 1.0f) * errorFactor;
// 放物線の高さ（Y軸）の計算
ballVY = (HOOP_Y - startY + 0.005f * (frames * (frames + 1)) / 2.0f) / frames;

// ジャンプシュートよりも打点が低く、直接ゴールを狙う軌道設定である。
ballVX = (targetX - startX) / frames;
ballVZ = (targetZ - startZ) / frames;
// 放物線の高さ（Y軸）の計算
ballVY = (targetY - startY + 0.005f * (frames * (frames + 1)) / 2.0f) / frames;

ballVYの計算は、物理の公式（等加速度運動）を使って実装した。
毎フレーム 0.005f ずつ重力でボールが落ちていく設定
ゴールに届くまでの時間（frames）から逆算して、「どれくらいの力で上に投げ上げれば、重力で落ちていった時にちょうどゴールの高さ（HOOP_Y）にピタッと合うか」を計算



【関数の使用目的と数学的アプローチ】
・sqrt関数 ：
  キャラクター同士の距離、ボールとゴールの距離、3Pラインの判定など、三平方の定理を用いた3D空間内の正確な距離計算・当たり判定を行うために多用した。
・sin / cos関数 ：
  キャラクターの歩行アニメーション（手足の滑らかな振り子運動）や、ドリブル時にボールが手から床へバウンドする自然な上下運動を、時間経過に応じた角度変化として表現するために使用。
・gluLookAt関数 ：
  手前に転がったボールがカメラのクリッピング領域（視界の手前の壁）に入って消失するバグを防ぐため、視点を上方に上げつつ後方に下げ、注視点をミリ単位で調整することで、コート全体を見渡せる最適な俯瞰カメラを実現しました。
